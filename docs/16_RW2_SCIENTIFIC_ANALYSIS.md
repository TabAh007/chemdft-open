# RW-2 — Scientific analysis, exports and comparison

Read-time projections of already persisted, validated evidence. Nothing here runs an engine, changes a
result's authority/validation/verification state, or alters a numerical algorithm.

## Exports

`GET /v1/projects/{project}/calculations/{calculation}/exports` lists what the stored evidence can honestly
export (and the exact reason for anything it cannot). `GET …/export?format=<key>[&variant=<key>]` downloads it.
Every download goes through `download_response.attachment_response` (safe filename, `no-store`, `nosniff`,
`X-ChemDFT-Evidence-Use` = `CURRENT | HISTORICAL_ONLY | UNKNOWN | NO_RESULT`; the Next proxy forwards these four standing headers only when each is a bare upper-case token, and forces `no-store` on any response that carries one) and, in the browser,
`lib/download.ts`. The existing lineage export (`/results/{id}/export`), structure exports, native artifact
downloads and viewport PNG export are unchanged.

| format key | file | content | availability |
|---|---|---|---|
| `result-json` | `chemdft.result-export.v2` JSON | payload exactly as stored (+ its SHA-256), summary with units, engine/method/basis, structure identity, effective + stored scientific state, independent-verification statement, provenance lineage | a published result exists |
| `trajectory-xyz` | multi-frame XYZ (Å) | every stored optimization frame, original atom order; energy (Eh), gradient (Eh/bohr), frame kind in each comment line | the calculation stored ≥1 frame |
| `spectrum-csv` (`ir`, `raman`, `uvvis`) | CSV with `#` metadata header | stick data, one row per stored normal mode / excited state; no broadening, no peak picking | frequency result with IR intensities / Raman activities, or TDDFT result |
| `cube` (`<field artifact id>`) | Gaussian CUBE (bohr) | a **stored** `chemdft.volumetric-field.npz` (electron density e/bohr³, ESP a.u., MO amplitude bohr⁻³ᐟ²) with atoms, origin, axis vectors, field identity | the field was already generated by the viewer |

CUBE details: lengths are converted with one factor (1 bohr = 0.529177210903 Å, CODATA 2018); x is the slowest
and z the fastest axis, six values per line, a new line after each z-row; values are written with 9 significant
digits so the stored float32 round-trips exactly; atom charge column is the atomic number (all-electron fields).
Evidence standing is in the first comment line (`EVIDENCE_USE=CURRENT|HISTORICAL_ONLY|UNKNOWN AUTHORITY= LINEAGE= VERIFICATION=`), so it survives the file leaving the API; a missing effective state is `UNKNOWN`. Orbital identity is in the comment lines (positive atom count, no orbital-count header). Independent checks on
real PySCF fields: ∫ρ dV = 9.62 e for water (the app's own 5 % QA tolerance), ∫ψ² dV = 1.000 for every exported MO.
Legacy `ORBITAL_GRID` artifacts have no explicit field unit and are **not** exported; export never computes a grid.

## Comparing calculations

`GET …/calculation-comparison?result_id=…` (2–8 results; first = reference; differences are *other − reference*).
Per pair, rules R1–R8 (see `calculation_comparison.py`) are evaluated from stored specifications:

* any `FAIL` (different molecule, charge, multiplicity, method/basis/dispersion/solvation) → **NOT_SCIENTIFICALLY_COMPARABLE**, no difference is formed (so xTB vs Psi4/PySCF totals, or DFT+D4 vs uncorrected DFT, are never subtracted);
* else any `LIMITATION` (historical evidence, other engine/version, different geometry with its Kabsch RMSD, differing thermochemistry T/p) → **COMPARABLE_WITH_LIMITATIONS**;
* else **DIRECTLY_COMPARABLE**.

Agreement never changes a verification state; inactive evidence keeps its recorded values but is labelled
`HISTORICAL_CONTEXT`. CSV/JSON export: `…/calculation-comparison/export?format=csv|json`.

## Jobs

`GET …/compute/jobs/{job}/diagnostics` and `…/logs/{artifact}`: persisted executions, attempts, active lease,
native artifacts, heartbeat freshness judged by the scheduler's own lease deadline, and a bounded, sanitized log tail.
No percent-complete is ever produced (`progress_reported` is always `false`); live log streaming is not available —
logs exist once an attempt has persisted them.

## Verification harnesses

* `python3 tools/run_isolated_e2e.py --suite rw2-analysis --api-port 8181 --web-port 3181` — disposable stack, real xTB/PySCF/Psi4/CREST/DFT-D4.
* `python3 tools/rw2_evidence_stack.py` — disposable **copy** of the accepted 2026-10-06 PySCF evidence, then
  `playwright test --config playwright.rw2-evidence.config.ts` (see the spec header).
