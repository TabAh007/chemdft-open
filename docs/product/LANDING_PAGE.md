# Landing Page and Public SEO UX

## Job and mode

Mode: **Persuade**, grounded in real product mechanism. A computational or experimental researcher must understand within the first viewport that ChemDFT joins real engines, experimental comparison, deterministic visualization, and AI-guided workflow—and know how to start or inspect a demo.

## Hero

Brand: **ChemDFT**

Headline: **Computational chemistry, without the old workflow.**

Support: **Run DFT, analyze experimental data, visualize molecular properties, and work with an AI scientist directly in your browser.**

Actions: **Start calculating** (primary) and **View demo** (secondary). Do not require sign-in merely to view an honest demo explanation.

The dominant hero artifact is a production-realistic interactive WebGL molecule/scene concept when implementation reaches that capability, with deterministic/synthetic-demo data clearly labeled. Compact toggles—Molecule, HOMO, LUMO, ESP—change actual prepared scientific scene layers without model calls. If WebGL is unavailable/reduced-motion/data-saving, use a verified static fallback from the same scene, not generic stock molecule art.

Trust line: `PySCF · xTB · CREST · GPU4PySCF · Psi4`, with wording that describes integration/architecture accurately and no implied endorsement.

## Page sequence

1. Hero mechanism and action.
2. Actual workflow strip: request → review plan/cost → real engines → linked result/evidence.
3. Product workspace preview centered on a molecule + FTIR linked selection, not a collage of cards.
4. AI Scientist plan block paired with Advanced settings to prove AI-first and expert-equivalent.
5. Deterministic scientific results and Scientific Result Firewall.
6. Experimental + calculated modalities and linked comparison.
7. Compute flexibility and transparent cost/cap model; no unsupported provider/price claims.
8. Provenance trace example: value → job/method/input/artifact/source.
9. Supported analyses in a dense capability matrix with “available/planned” truth labels.
10. Conceptual pricing structure; no values until approved.
11. Useful SEO/tool entry points when real tools exist.
12. Footer with documentation, methods, security/privacy, legal, status/contact.

Avoid giant feature-card grids, identical three-column feature rows, stock people, sparkles, fake metrics/customers/benchmarks, vague “revolutionize” copy, decorative gradients, and a static molecule when a truthful interactive artifact is feasible.

## Reusable public-page template

Future routes `/dft-calculations`, `/online-dft-calculation`, `/computational-chemistry-software`, `/quantum-chemistry-software`, `/molecular-modeling`, `/homo-lumo-calculator`, `/ftir-analysis`, `/nmr-analysis`, `/xrd-analysis`, `/uv-vis-analysis`, `/gaussian-alternative`, `/webmo-alternative`, `/orca-alternative`, and `/pyscf-online` use a shared content grammar, not duplicated thin pages:

- exact task/problem and who it is for;
- interactive or real example with provenance/demo label;
- inputs → method/engine → outputs/limits;
- workflow and expert controls;
- validation, uncertainty, security, and cost behavior;
- relevant FAQ/documentation/citations;
- one primary action and related tools.

Comparison pages are factual, respectful, updated, and distinguish interoperability from affiliation. SEO pages are localized with canonical/alternate links and never expose private project routes.

## Future free tools

Candidate entry utilities: molecule/XYZ/SDF viewer, prepared HOMO/LUMO visualizer, spectrum analyzer, basis/method helper, and Gaussian output viewer/converter. Ship only when each provides real deterministic value, honest file handling, and a path into a project—never as empty keyword pages.
