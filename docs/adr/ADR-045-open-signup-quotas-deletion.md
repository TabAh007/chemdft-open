# ADR-045: Open signup (switch OFF), per-account quotas, data export and deletion

Status: Accepted; **signup stays closed until the owner says "open signup"** and email delivery works. Date: 2026-11-03. Release 0.0.10.
Related: [ADR-044](ADR-044-orcid-integration.md), DECISIONS.md, EMAIL_DELIVERY_DESIGN.md, AI_PROVIDER_TERMS_FOR_BETA.md.

## Decisions

1. **Signup is a switch, off by default, failing closed.** Web: `CHEMDFT_SIGNUP_OPEN=true` AND a working email transport AND an authentication database migrated for the new columns; any missing piece keeps signup closed and the sign-in page unchanged. API: `CHEMDFT_SIGNUP_OPEN` (default false) makes the API refuse to provision a self-signup identity (`signup_closed`) even if the web layer were misconfigured. ORCID stays link-only.
2. **A self-signup account is marked by the server, never by the browser.** Better Auth `signupSource="self"` (input:false) is set for any account created through an HTTP request; the controlled/invited accounts are created by a script and are never marked. The JWT carries `signup_source`, `terms_version`, `terms_accepted_at`; the API creates an `account_profiles` row at first provisioning. **Accounts without a profile row (the owner and invited researchers) are never subject to the new quotas.** This overrides the earlier "no per-user limit" decision only for self-signup accounts.
3. **Verification before any compute or AI.** Better Auth `requireEmailVerification` blocks sign-in until the link is opened; the API independently refuses compute/AI with `EMAIL_NOT_VERIFIED` while `email_verified_at` is empty.
4. **Quotas** (config keys, server-enforced, named errors, every refusal audited, shown read-only in Settings): jobs/day 5, jobs/30 days 40, concurrent jobs 2, AI runs/day 20, projects 5, stored files 200 MB, single upload 25 MB. Compute hours remain bounded by the existing AWS guard (monthly hours, two-hour session).
5. **AI for new accounts is OFF** (`CHEMDFT_AI_FOR_NEW_USERS=false`, error `AI_NOT_ENABLED`) until the owner has read the provider-terms document.
6. **Abuse limits:** per-IP sign-up limit 5/hour and sign-in 10/minute (Better Auth, stored in the authentication database so serverless instances share it), per-address 3 verification/reset mails/hour (own counter in the same table), disposable-domain blocklist (curated, incomplete by nature), one generic response for an existing address, signup attempt audit lines with hashed references only.
7. **Data rights:** `GET /v1/me/export` (zip of JSON; the caller's own data through the same authorized read actions as the app; no secrets, no file bytes) and `POST /v1/me/delete` (typed-email confirmation): cancels active jobs, deletes the content rows of owned, unshared projects (project shell kept so append-only audit/ownership/ledger rows keep their foreign keys), deletes stored objects, removes ORCID link and AI preferences, anonymises the user and disables it (the opaque identity subject row stays so a stale token resolves to `account_disabled`). The web route then deletes the Better Auth user, accounts and sessions. Backups keep older copies up to 30 days; audit rows hold only a pseudonymous id.
8. **Migration `0030_beta_readiness`:** two new tables (`account_profiles`, `account_audit_events`) and one index; nothing altered, dropped, rewritten or inserted. The authentication database (Neon, owned by Better Auth) additionally needs additive columns on `user` and the `rateLimit` table before signup can open (`pnpm --filter @chemdft/web auth:migrate`, not run by this release).

## Known limits

Hard deletion was verified on real PostgreSQL 17 (foreign keys enforced) for a project with a structure and a file; **not** for projects containing compute jobs, results or AI conversations (the generic purge covers them by table metadata and is unit-tested on SQLite only). Shared projects are not purged. Email delivery, rate limits on the hosted site and the full signup flow on Vercel are NOT VERIFIED live.
