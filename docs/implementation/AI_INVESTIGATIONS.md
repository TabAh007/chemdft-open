# AI Investigations

Phase 10 adds a bounded, project-scoped Investigation domain on top of the Phase 8 AI Scientist and existing compute/evidence services. An investigation persists an objective, hypotheses, immutable plan revisions, steps, observations, and assessments. Its lifecycle (`DRAFT`, `PLANNED`, `WAITING_FOR_APPROVAL`, `ACTIVE`, `WAITING_FOR_RESULT`, `WAITING_FOR_USER`, `PAUSED`, `COMPLETED`, `FAILED`, `CANCELED`) is separate from calculation lifecycle.

AI-generated hypotheses are always `AI_HYPOTHESIS`; that class cannot publish experimental, extracted, digitized, or calculated values. Observations reference existing typed CalculationResult, ExperimentalDataset/DigitizedDataset, or EvidenceCandidate records and store only a summary plus reference. Plans are proposals, not authorization; expensive work remains behind the existing Tool Registry and approval verifier. Policy bounds are server-owned and cannot be raised by model output.

The execution seam supports explicit start/resume, exact-step approval records, stable step-scoped idempotency keys, reuse of an equivalent calculation input/result, durable `WAITING_FOR_RESULT` state, and result-to-observation linking after the normal calculation read path reports a Firewall-published result. Runtime step, calculation, elapsed-time, estimated compute, and AI-call ceilings are enforced before dispatch.

The `chemdft-investigation-worker` entrypoint provides both a one-shot mode (`--once`, or `CHEMDFT_INVESTIGATION_WORKER_ONCE=1`) and a continuous polling mode. It claims one `ACTIVE` or `WAITING_FOR_RESULT` investigation with a compare-and-set lease, renews that lease while invoking the application service, and clears expired leases after a worker crash. The service remains the only owner of Tool Registry, approval, compute, provenance, and result-firewall side effects.

After each asynchronous result, the worker invokes a provider-neutral model gateway with a strict `InvestigationDecision` contract. Decisions are persisted by cycle fingerprint and can propose one bounded next step, assess and complete, report an inconclusive result, or request user input. Model output is untrusted: it cannot create an observation, change authority, raise budgets, or bypass approval. Unsupported objectives therefore settle in `WAITING_FOR_USER`; a user answer re-enters the same bounded loop.
