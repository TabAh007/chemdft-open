# Project Overview redesign (DESIGN-04)

Status: implemented and approved in worktree `design/overview-redesign-v1`; **committed locally only, not pushed, not
deployed**. Nothing here changes backend, schema, AWS, auth, engines, the Result Firewall or AI
provider configuration.

## What the page is

`/[locale]/projects/[projectId]/overview` renders `ProjectOverview`
(`apps/web/src/app/_components/overview/`). It answers four questions and leaves the rest to the top navigation
(Workspace, Results, Compare, Jobs, Claims, Paper vs ChemDFT, Settings), which it does not duplicate:

1. **What project and structure?** `overview-header.tsx`: name and active structure; role, dates, slug and project ID
   are behind "Project details". Below it, a five-cell summary strip (structures, calculations, results, evidence,
   workflows available including the recommended action). Unavailable workflows are not a headline metric.
2. **What has been done?** `overview-stage.tsx` / `overview-viewer.tsx`: a large interactive view of the committed
   molecule or periodic cell with its own facts, and, beside it, *Results & provenance* (latest published result with
   standing and validation shown separately; failed, pending and older calculations on their own lines) and a short
   *Scientific status*.
3. **What next?** One *Recommended next action* (server order, first available action with a real destination).
4. **Where to continue?** *Continue your research*: up to four more contextual actions (`planContinue`), then
   **Browse all workflows**, a disclosure holding the whole catalogue: goal selector, every workflow grouped, every
   unavailable reason with its classification, recorded server facts and notices. Recent activity sits beside it.

Each available action is shown once: the recommendation, the structure card (Open in workspace / Edit structure,
only when the server offers them and they are not the recommendation) or the Continue list. The caption under
"Continue your research" reconciles the count ("5 available: 1 recommended, 1 on the structure card, 3 listed here").
Everything else remains in Browse. A selected goal (including `?navigator_goal=`) opens Browse.

Periodic structures say "Atoms in cell", show lattice parameters, and give the reduced formula and the stored cell
composition separately (`crystalFormulas`, arithmetic on the stored sites). Layout follows the width the page is
given (container queries), with the AI Scientist dock open or closed.

## Where every number and word comes from

| Shown | Source (existing) |
|---|---|
| Name, role, dates, slug, ID | `GET /v1/projects/{id}` (`ProjectRead`). There is **no description or research-status field**, so none is shown. |
| Goals, available actions, blocked actions and reasons, recorded facts, notices | `GET …/navigator` through `useOverviewNavigator` (same inputs, refresh triggers and 10 s running-job poll as `ProjectNavigator`). Eligibility is the server's; the page only groups and labels it. |
| Active structure | the exact version the Navigator is scoped to (`facts_summary.structure_id/_version_id`), read with `getStructureVersion`. |
| 3D view | the product `MolecularRenderer`, fed by `buildScientificScene` → `structureFromScene` (stored bonds stay canonical; display bonds are inferred only when none are stored and the page says so). The camera zoom is a deterministic fit computed from the renderer's projected bounds of the real atoms (1–2.2×, camera only, re-fitted on resize unless the researcher zoomed). Static SVG fallback of the same coordinates when WebGL is unavailable. |
| Counts and activity | the project catalogue already loaded by the Explorer (`useWorkspaceState().catalog`). |
| Results and failures | `GET …/research-overview` rows (server standing and verification text; one row per calculation). |

Counts keep sources apart: submitted vs imported calculations, published vs imported results, committed versions vs
unreviewed candidates. Failed calculations are their own rows and never change another calculation's result.

## Scientific invariants kept

- No scientific value, structure, bond, cell, citation or capability is generated by the UI.
- The page is read-only: no calculation, import, AI request or approval is started from it (guarded by a unit test).
- "Available" never means executable: the page says so, and unsupported tasks appear as unavailable with the
  server's reason, labelled **Worker capability**, **Unsupported method**, **Scientific prerequisite**,
  **Project record** or **Access**, each kept apart (`restrictionSummary`, `REASON_KIND`).
- Imported values are labelled "not ChemDFT results" and never counted as published results.
- Structure source and review state use the workspace's words (`USER_SUPPLIED`, `NOT REVIEWED`, …).

## AI Scientist dock

The header toggle and the dock's close button dispatch `chemdft:toggle-dock`, which only the Workspace route
handled, so they did nothing on the Overview. `useOverviewDock` now handles it on the Overview with the same shell
class, event and stored preference keys as the Workspace (the choice carries between routes). At ≤ 760 px the dock is
the same bottom sheet as in the Workspace (`shell.css`), closed until asked for.

### HTTP 404 "Scientific context unavailable" — UNRESOLVED AI Scientist integration issue (separate task)

- The failing request is `POST /api/chemdft/v1/projects/{id}/ai/context` (panel → Next proxy → API).
- The message text `HTTP 404: Not Found` is FastAPI's **route-level** default (`detail: "Not Found"`). A missing or
  forbidden project returns a specific text (`Project not found.` / `Project edit access required.`), and the Next
  proxy never produces 404 itself.
- The route exists at HEAD (`services/api/src/chemdft_api/main.py`, `read_product_context`, since 8dcd7bb) and the
  offline API tests `test_empty_context_is_bounded_server_authority` and `test_context_role_is_current_server_membership`
  pass (9 passed, run 2026-10-19).
- Conclusion (evidence-based, root cause **not verified**): the API process that served the reported screenshots did
  not expose that route (stale or different API build or base URL). Check with
  `curl -s <API>/openapi.json | grep ai/context`, restart the API from this checkout, or confirm
  `CHEMDFT_API_BASE_URL`. The Overview change does not touch this path; the error stays visible by design and is left unresolved here (it belongs
to the separate AI Scientist integration work; nothing in this change hides, handles or works around it).
- The 404 in the local QA screenshots is a different, known cause: the QA mock API does not implement the route.
