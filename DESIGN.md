# Design System: ChemDFT

**Authority.** This file is the authoritative visual-design contract for ChemDFT. It *synthesizes* and does not replace [`docs/design/DESIGN_SYSTEM.md`](docs/design/DESIGN_SYSTEM.md), [`docs/design/ANTI_SLOP_CHECKLIST.md`](docs/design/ANTI_SLOP_CHECKLIST.md), [`docs/product/LANDING_PAGE.md`](docs/product/LANDING_PAGE.md), [`docs/design/SCIENTIFIC_VISUALIZATION_UX.md`](docs/design/SCIENTIFIC_VISUALIZATION_UX.md), `docs/implementation/CHEMDFT_PROJECT_MEMORY.md` and `PRODUCT.md`. Where this file is silent those documents govern; where they conflict with this file on **public-site presentation** this file wins; on **scientific integrity, accessibility and the Scientific Result Firewall** they always win. Tokens in the frontmatter are normative and mirror the values currently shipped in `apps/web/src/app/landing.css` (`--cdf-*`, `--home-*`) and `shell.css` (`--guided-*`); the app-workstation values in `DESIGN_SYSTEM.md` remain the source for the authenticated Advanced workbench. No token here may be used to alter scientific meaning.

## Overview

**Creative North Star: "The Instrument Plate."** ChemDFT presents science the way a good journal plate and a calibrated instrument do: one precisely rendered object, labelled with its provenance, set on a calm field, with every number traceable. It is **scientific publication × precision instrument × CAD/CAE workstation × premium research software**.

It is **not**: generic SaaS, an AI startup, crypto/sci-fi, glassmorphism, a card-heavy marketing dashboard, or neon molecular visualization. A reader should feel *this is serious scientific software built by people who care about correctness*, within one viewport.

Personality: precise, evidence-aware, calm, direct, scientifically literate (`PRODUCT.md`). Premium comes from **craft of the one hero object, restraint, scale contrast and exact alignment**, never from decoration. The public site is a Persuade surface built on a real mechanism; the application is an Operate surface. They share tokens, type, hairlines and the molecule renderer so the homepage previews the real product.

Voice rules:
- Say what the software does and what it does not. "Available / planned" truth labels stay.
- No fake metrics, customers, testimonials, benchmarks or prices. Pricing and public sign-up are unavailable and must read as such.
- Avoid generic "AI-powered" phrasing. AI is described as an assistant that plans, explains and cites; engines calculate.
- Emphasize, in this order: real scientific engines, verifiable outputs, provenance, AI-guided workflow.

## Colors

A cool, light-first, hairline-driven palette with **one** accent. Colour carries meaning, never mood.

- **Canvas / Surface** (`#f7f9fb` / `#ffffff`): the page is a calm cool-grey field; evidence panels are white. Do not tint the page toward warm beige or add colour washes.
- **Ink** (`#18212b`) for text and scientific values; **Ink-muted** (`#52606d`) for metadata. Muted text on canvas must keep ≥ 4.5:1.
- **Line / Line-strong** (`#d6dde4` / `#b8c2cc`): 1px structure. Hairlines are the primary hierarchy device.
- **Accent** (`#1565a7`): the single interactive/primary colour (links, primary button, active edge). Never as a gradient, glow or large fill block.
- **Observatory dark** (`#101a24` with `#2a3947` lines, `#e6edf3` ink): the one permitted dark register, used sparingly (see Page composition). It is a deep desaturated blue-black, not black, not navy-purple.
- **Inside the dark act** (the only place these appear): the flow rail is `observatory-rail` (`#5d7c97`, hairline `observatory-rail-dim` `#3d5266`), accent text uses `observatory-dark-accent` (`#7fb5e6`), and the **AI lane** — the only categorical distinction on the page — is `observatory-ai` (`#e3b075`, always paired with a dashed node and the word "AI") against the platform's blue. Check/cross glyphs on dark use `observatory-success` (`#6fcf97`) and `observatory-error` (`#f08a84`), which keep ≥ 4.5:1 on `observatory-dark` where the light-mode semantic colours would not. On light surfaces, small text on the faint tier uses `ink-faint` (`#5a6878`, 5.3:1 on white); the shared UI faint ink (`#718096`) is 4.0:1 and must not carry small text. A running-engine label uses `status-success-strong` (`#1a6a3f`).
- **Semantic**: success `#237a4b`, warning `#9a6500`, error `#b4232b`. Always paired with a glyph or word, never colour alone.
- **Scientific colour** is allowed only where it has meaning and a legend: orbital phase (`#4a6fd1` positive / `#e39a52` negative, "phase sign, not charge"), ESP scale, provenance roles from `DESIGN_SYSTEM.md`, and **CPK-style element colours** for atoms (see Molecular Rendering System). No decorative categorical colours.
- **Guided workstation** uses `#f8fafc` / `#ffffff` / `#2563eb`. The public site's accent (`#1565a7`) and the Guided accent differ slightly today; converging them is a PF-3B3 decision, not an open licence to introduce a third blue.
- **AI Scientist panel** (UI-1 pass 4, 2026-10-17): the `--ai-*` tokens in `apps/web/src/app/ai-scientist.css` alias the workstation tokens (accent `#1565a7`, lines, ink, 2–4px radii) so the panel reads as part of the Inspector/dock rather than an embedded widget. This does not decide the Guided accent question above.

Forbidden: decorative gradients, mesh/aurora backgrounds, glow, neon cyan/magenta, purple-to-blue "AI" gradients, translucent glass fills.

A serif for editorial captions is *not* adopted; "publication" character comes from figure-style captions, tabular numerals, hairlines and metadata discipline, not from a typeface change. Rules:
- Heading hierarchy is shown by **size and weight contrast**, not colour or decoration. There is no gradient text, no outlined text, no text shadow.
- Never set body copy in monospace. Monospace is for values, identifiers, method strings (`HF / STO-3G`, `PySCF 2.14.0`), hashes and kickers.
- Never translate element symbols, method names, basis sets, formulae or engine output; localized copy must tolerate +35% length (TR/RU/DE) without fixed-width labels.
- Use real chemical typography: subscripts (Cr₂O₃), Å, ° and minus signs (−), not hyphens or "A".
- Hero H1 should not exceed ~68px on desktop; the audit found the previous 70px/−0.04em two-line treatment generic. Personality comes from scale contrast against small precise metadata, not a larger headline.

## Layout

- **Container**: max 1240px with 32px desktop gutter, 16–20px mobile gutter. Wide "edge-to-edge" moments are explicit exceptions (see composition).
- **Grid**: 12-column, aligned to the 4/8 spacing scale (`4, 8, 16, 32, 64`). Alignment is exact; ragged, centered stacks are avoided.
- **Asymmetry is the default.** Use 5/7 or 4/8 splits, an offset heading column with a wide evidence column, or a full-bleed object with a narrow caption rail. Equal columns of equal weight are a smell.
- **Act spacing**: vertical whitespace between acts scales with `clamp(72px, 10vw, 140px)`; whitespace *within* an act stays tight (16–32px). Large empty regions without a purpose (the audit's floating hero text block) are a defect; whitespace must frame an object, not pad a band.
- **Density**: the public site is moderate density with high-density *evidence* (tables, metadata, real screenshots). The workstation remains dense (13px/18px base, 32px rows).
- **Responsive**: desktop-first for the workstation, but the **public site is designed mobile-first for narrative and desktop-first for the hero object**. See Mobile rules.

### Page composition and cadence

The public site is **not a stack of equal sections.** Cadence alternates between five registers; no two adjacent acts share a register:

1. **Immersive demonstration** — the interactive object dominates (Act I).
2. **Explanation** — short, text-led, with the object persisting (Act II).
3. **Evidence** — dark, quiet, hairline-structured proof (Act III).
4. **Product interface** — a large real screenshot/embed is the hero (Act IV).
5. **Quiet / reproducibility** — dense hairline table on the light canvas (Act V).
6. **Final action** — restrained, short.

Rules:
- **Whitespace**: generous around the hero object and the final action; tight inside evidence. Whitespace is allocated per act, not uniformly.
- **Section transitions**: no hard colour bands butted together. Transitions are carried by a hairline, by the persistent crystal moving/changing state, or by a deliberate one-way shift into the dark act and back. A 1px `line` rule plus a figure-number marker is the default divider. Never a wave, slant, gradient fade or blob.
- **Edge-to-edge moments**: at most two (the Act I crystal stage and the Act IV workstation). Elsewhere, content sits on the container.
- **Dark section usage**: one dark act only (Act III, the Scientific Result Firewall/provenance proof) on `observatory-dark`. Dark is for *authority and proof*, never decoration or "premium" mood. No second dark band, no dark footer unless it is the same act continuing.
- **Screenshot scale**: real product screenshots are shown **large and legible**: ≥ 8 of 12 columns on desktop and full-width (bleeding to gutter) on mobile, with text in the capture readable at 100% zoom. A tiny screenshot is a defect; if the text cannot be read, crop to the meaningful region instead of shrinking. Screenshots are real (water HF/STO-3G etc.), carry a figure caption with calculation identity, and are never mocked or altered.
- **Hairlines over boxes**: structure comes from 1px rules, rows and alignment. Hairline tables replace feature cards.
- **Panels**: allowed only for (a) the interactive viewer's control strip, (b) a screenshot frame, (c) a genuine standalone object. Max one panel level; never panel-in-panel. 0–2px radius, 1px border, no shadow.
- **Cards**: exceptional. A card is a standalone, selectable or comparable *object* (a pricing tier later, a single downloadable example). Cards are never the layout primitive for features, steps, engines or benefits. No three-up card rows.

## Elevation & Depth

Flat and hairline by default. Depth on the page comes from **tone, scale and the 3D object**, not from CSS shadow.

- Docked or in-flow elements: no shadow, 1px border at most.
- True overlays only (menu, popover, dialog): the single shadow vocabulary from `DESIGN_SYSTEM.md` (`--guided-shadow-md` class). No large soft "floating card" shadows.
- The crystal stage may have an extremely subtle cool ground (a barely lighter/darker radial of the canvas colour, ≤ 4% luminance difference) so the object is seated; this is lighting of the scene, not a decorative gradient, and must not read as a spotlight or glow.
- No glassmorphism/backdrop-blur, no blurred coloured blobs, no inner glows.

## Shapes

- Radius: `0–2px` for panels, buttons, tabs, table frames; `4px` for inputs and small controls; `6px` only for transient overlays. **No giant rounded panels, no pill buttons, no pill tab bars.**
- Segmented controls and tabs use a baseline/edge selection, not filled pills.
- Borders are 1px hairlines; selection uses an accent edge or outline, not a thick rounded fill.
- The grid-line background pattern (currently `landing.css:70`, flagged by the Impeccable detector as `codex-grid-background`) is prohibited as a hero/viewer backdrop. A measurement grid is allowed only on a genuine canvas where it carries units (e.g. a calibrated plot or a toggled, labelled lattice grid in the viewer).

## Components

- **Buttons**: compact rectangles, 36px tall (44px touch targets on mobile via padding/hit area), 2px radius. Primary = solid `accent` with white text, one per view. Secondary = white surface, 1px border. Tertiary = text link with underline on hover only. No icon-in-circle, no arrows animating, no gradient. The signed-out hero shows exactly one primary (Sign in) and one secondary (See how it works).
- **Viewer control strip**: a thin hairline-bounded strip beneath or over the stage. **Reduced controls**: at most one segmented control for representation (Ball-and-stick / Polyhedra), one for extent (Cell / Supercell), plus a single overflow or "Reset view". Zoom ± and Pause rotation become gestures/keyboard and an accessible pause control, not a row of underlined text links.
- **Provenance / metadata block**: a hairline definition list (label in mono, value in mono/Inter), figure-captioned. This is the "publication" signature of the site and replaces cards.
- **Screenshot frame**: 1px line, 0–2px radius, no shadow, caption below. The frame never crops the product's own chrome in a misleading way.
- **Navigation**: 54px header, hairline bottom, quiet text links, one primary action at the end, locale switcher present. Mobile collapses to a menu button without losing the primary action.
- **Status marks**: ✓ / × / ○ / ◐ glyph + text. Not coloured dots alone.

## Do's and Don'ts

**Do**
- Make one object (the α-Cr₂O₃ crystal) the unmistakable hero and let everything else orient around it.
- Keep geometry authoritative in every preset; change only lighting, camera, materials and composition.
- Pair every scientific claim with a source, method or screenshot; label synthetic or reference content.
- Use hairlines, alignment, scale contrast and tabular metadata for hierarchy.
- Support reduced motion, keyboard use, and a static fallback rendered from the same scene.
- Verify with desktop (1440) and mobile (390) renders and Lighthouse; keep CLS at 0.

**Don't** (public-site anti-pattern list, binding)
- Grid-line hero backgrounds, dotted/graph-paper fields.
- Card soup, nested panels, giant rounded panels, shadowed section boxes.
- Excessive pills or pill tab bars; pill-shaped CTAs.
- Meaningless gradients, mesh backgrounds, AI blobs, aurora, glow.
- Glowing atoms, bloom, lens flare, lens distortion, neon molecules.
- Starfields, floating particles, orbiting electrons, decorative molecules in the background.
- Oversized fake metrics, "10× faster", counters, invented benchmarks.
- Logo walls without meaning; engine names are shown only with their honest availability status, never as an endorsement wall.
- Identical three-column feature rows or repeated kicker-H2-paragraph-box bands.
- Tiny, illegible product screenshots.
- Long engine ledgers (the audit's full engine list is collapsed to the engines that actually run, with a link to the full status).
- Generic SaaS headlines ("Supercharge your research", "Unlock insights", "AI-powered", "Revolutionize").
- Continuous fast molecule rotation, scroll-jacking, floating/bobbing cards, gratuitous parallax.
- Visualization altered for aesthetics (moved atoms, invented bonds, smoothed lattice).

## Molecular Rendering System

The future **ChemDFT Molecular Rendering System** is the single Three.js-based renderer (React Three Fiber on the web) used by the homepage, the Guided workspace and exports. It consumes the renderer-neutral `ScientificScene` (ADR-012/018) and is bound by the Visual Bond Firewall (`CHEMDFT_PROJECT_MEMORY.md` §3): displayed bonds are visualization aids unless present in authoritative source topology, and **rendering never alters chemistry, coordinates or lattice**. Three.js Studio and 3Dmol.js Scientific Mode continue to consume the same scene. This section defines visual principles and acceptance criteria; implementation is a later phase.

### Atoms
- Smooth, sufficiently tessellated spheres (no visible faceting at hero size; ≥ 48 segments or equivalent/impostors).
- **Scientifically recognizable element colours** (CPK/Jmol-family: O red, Cr a steel blue-grey as in common crystallography practice, C grey, H white, N blue, etc.). Colour tables are fixed and documented; desaturation for tone is allowed, hue reassignment is not.
- Restrained physically-based material (e.g. `MeshPhysicalMaterial`/`MeshStandardMaterial`): **moderate roughness (~0.35–0.55), metalness ≈ 0**, subtle specular response and a faint clear-coat at most. **No plastic/candy look**: no strong white hotspot, no saturated "bubble-gum" colour, no transparent gel.
- Radii are a documented, user-selectable convention (covalent / ionic / van der Waals / ball-and-stick scale). The convention is stated near the viewer. The default must keep bonds visible and avoid atom overlap clutter.

### Bonds
- Cylindrical geometry with correct end intersections: a bond meets the atom sphere surface cleanly, with no gaps or protruding caps.
- **Optional split colouring**: each half takes the colour of its bonded element, with a hard or very short soft transition at the midpoint. Default for Editorial; selectable for Scientific.
- Subtle depth shading (lighting/AO, not outlines). Radius thin relative to atoms so atoms read first.
- No arbitrary decorative bonds. In crystals, display bonds follow a stated cutoff rule (e.g. Cr–O within a documented distance), labelled "display bonds (inferred)" per the Visual Bond Firewall.

### Crystallographic cells
- **Authoritative lattice geometry** from the structure (`a, b, c, α, β, γ` → lattice vectors). α-Cr₂O₃ is drawn as the true hexagonal-setting parallelepiped (γ = 120°), never a rectangular box substitute.
- Thin, precise unit-cell edges (≈ 1–1.5px equivalent, constant screen-space width), low-contrast ink (`ink` at 50–70%).
- **Optional dashed/hidden-edge treatment** for Publication: visible edges solid, rear edges dashed or lighter.
- Cell axes labels (a, b, c) and origin marker available, off by default in Editorial, on in Publication. Supercell display is labelled display-only and shows the generating repetition ("2×2×2").
- Correct periodic-image handling: atoms on cell boundaries appear on all equivalent faces/edges as the lattice demands; no atoms are dropped, shifted or duplicated for composition.

### Polyhedra
- **Translucent, thin-surface scientific overlays** (here CrO₆ octahedra): restrained opacity (≈ 0.12–0.25 face fill), a single desaturated tint derived from the central cation's colour, **subtle edges** (hairline, ≈ 40–60% opacity), back faces handled so internal depth is readable (depth-sorted or order-independent transparency).
- **Atoms and bonds remain visible** through and in front of polyhedra (polyhedra never occlude the atoms they describe).
- No opaque turquoise/teal plastic, no saturated fills, no hard-edged faceting artefacts, no polyhedra extending outside the displayed cell without a stated reason (clipping/ wrapping rules are explicit and documented).
- Coordination polyhedra are computed from the stated cutoff, not drawn by hand.

### Lighting
- A **broad, soft studio key** (large area/hemisphere-style key from upper front-left), a **controlled low-intensity fill** from the opposite side, and a **subtle rim/separation light** to lift edges from the background. Neutral-white light, consistent colour temperature.
- Environment lighting only as neutral studio IBL for gentle reflections; no coloured lights, no glow, no neon.
- Tone-mapping: standard filmic/neutral, colours must remain recognizably element-correct.

### Depth
- **Subtle ambient occlusion** (contact darkening where atoms/bonds meet) and a soft contact/ground shadow only if the stage has a ground plane.
- **No excessive bloom, no lens effects** (no DOF, chromatic aberration, vignette, flares, motion blur). Any post-processing is limited to AO and anti-aliasing and must be switchable off, with a no-post static fallback.

### Camera
- **Restrained perspective for marketing/Editorial** (narrow FOV ≈ 25–35°); no aggressive fisheye or exaggerated foreshortening.
- **Orthographic option** for Scientific and Publication modes (default for Publication).
- **Smooth damped movement** (critically damped orbit/zoom, no overshoot or spring wobble); motion eases to rest. Autorotation, if any, is slow (≤ ~4–6°/s), pausable, and disabled for reduced motion.
- The camera is an explicit, serializable view state (position, target, up, zoom/FOV, projection) so views are reproducible and exportable.

### Selection
- **Minimal halo/outline** (1–2px, accent or ink, never glow), with a mapped inspector row; emphasis coordinates linked views (peak ↔ mode ↔ atoms). Not colour alone: outline + label/inspector text.
- No sci-fi HUD, reticles, scanning lines, holographic overlays or animated brackets.

### Implemented in PF-3D (renderer v1)

The reusable renderer lives in `apps/web/src/app/_components/molecular-renderer/` (React Three Fiber + drei + N8AO). Structure state (`ScientificStructure`, `derive.ts`) and presentation state (`PresentationState`, presets, camera) are separate types; nothing in presentation can write to a structure. Review surface: `/renderer-review` (development only). Recorded decisions:

- **Element colours** come from the ChemDFT central element table (`@chemdft/scientific-scene`, CPK/Jmol). The renderer supplements only what that table lacks: Cr `#8a99c7` (Jmol; covalent radius 1.39 Å, Cordero 2008; colour-vision-safe alternative `#56b4e9`). Editorial tones colours hue-preservingly (never changes hue); Scientific and Publication use them as stored.
- **Radius conventions** (never copied by eye): *ball-and-stick* uses a labelled display scale `0.46·r_cov^0.6` Å (not a physical radius); *space-filling* uses Shannon effective ionic radii when oxidation states are stated (α-Cr₂O₃: Cr³⁺ CN 6 = 0.615 Å, O²⁻ CN 4 = 1.38 Å, which sum to 1.995 Å against the structure's 1.96–2.01 Å Cr–O distances, so spheres touch without overlap), van der Waals radii for molecules, covalent radii otherwise. The active model and citation are exposed with the representation.
- **Polyhedra**: derived from the structure's coordination rule (six O within 2.3 Å of each Cr, drawn only when the count is exactly six), faces from the convex hull, shown complete (ligands outside the cell are shown as periodic images, only in polyhedra mode). One flat translucent tint (opacity 0.20–0.22) so blending order is exact; hairline edges; atoms remain visible.
- **Cells**: displayed atoms are the block's sites plus periodic images on upper cell faces/edges (never duplicates); supercells are `[nx, ny, nz]` and `2×2×1` is a valid squat alternative to `2×2×2`; Publication draws hidden edges dashed.
- **Camera**: orbit camera (the structure never moves), cylinder-based framing exact for rotation about the vertical axis, damped distance changes, perspective fov 26° (Editorial) / orthographic (Publication), wheel zoom off, touch `pan-y`.
- **Post-processing**: only N8AO (Editorial) and neutral tone mapping + SMAA; no bloom or lens effects anywhere. The scene reads correctly with AO off.

## Motion and animation

Responsibilities are separated; **none of these libraries is installed in this phase**, and the current homepage must not add them yet.

- **React Three Fiber / Three.js** — scientific-object animation only: atom/bond representation changes, supercell expansion, polyhedra reveal, and camera movement. Animations are data-driven, deterministic and interruptible.
- **GSAP + ScrollTrigger** (future, PF-3B3+) — major scroll-linked storytelling: pinning the crystal stage, section state changes, camera/state choreography across the acts. Scroll-linked state must be a *function of scroll position* (scrubbed), not time-triggered.
- **Motion** (the Motion/Framer-class library, future, optional) — small UI transitions only: hover/focus, disclosure, tab/segment change, 80–240ms.

Rules:
- **Normal scrolling stays intact.** No scroll hijacking, no scroll snapping that fights the user, no wheel capture, no artificial scroll length without a visible purpose. Pinning is brief and the page remains navigable by keyboard, anchor links and the scrollbar.
- **Reduced motion** (`prefers-reduced-motion`) removes spatial transitions, scrubbed camera moves and autorotation; the story is told with static states (stepped frames) of the same scene. A **static fallback image/scene** from the same `ScientificScene` is used for no-WebGL, data-saver and print.
- No constant decorative motion. Idle motion is limited to an optional slow, pausable crystal drift.
- No floating/bobbing cards, no gratuitous parallax, no auto-playing looped video, no animated counters.
- Performance budget: LCP stays fast (currently ≈ 270ms dev), CLS 0, main thread free during scroll; the 3D canvas loads lazily with a same-scene static poster.

Implementation is **not** part of this phase. The page is **considerably shorter than the current ~9,333px mobile layout** (target ≲ 5,000px mobile; ≲ 4,000px desktop), with a persistent crystal as the connective thread.

## Mobile design rules

Mobile is **not** stacked desktop. It is a separately composed, shorter narrative.

- **Immediate value proposition**: H1 and the single primary action are visible in the first screen without scrolling past a toolbar.
- **Crystal visible early**: the crystal begins within the first viewport (it may sit above or behind the supporting copy's fold edge). Frame it for a portrait stage: re-orient/re-frame the cell so a tall hexagonal cell is not cropped or reduced to a thin stick.
- **Reduced controls**: one representation toggle and an optional overflow; no row of five text links; touch targets ≥ 44px.
- **Shorter narrative**: acts are condensed; Act II becomes a few swipe-free states, not five full steps. Long reference lists are collapsed behind disclosure.
- **Simplified animation**: no scrubbed pinned choreography on small screens; simple state changes with reduced motion honoured; autorotation off by default.
- **Readable workstation evidence**: product screenshots are cropped to the meaningful region at legible size (text readable without pinch-zoom), not shrunk full-frame.
- **Length**: no 9,000px+ marketing scroll unless justified; target ≲ 5,000px at 390px width. Verify with the Chrome DevTools MCP at 390×844 and 1440×900.
- Mobile supports review and orientation, consistent with `PRODUCT.md`: do not imply that full professional editing runs on a phone.
